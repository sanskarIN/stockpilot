# StockPilot v0.3.7

## Reporting Handler Capability Selection

v0.3.7 completes the next step of the bounded reporting rollout by teaching the HTTP reporting handlers to use the additive `repository.BoundedReports` capability when the configured repository provides it.

### Highlights

- supplier-performance now uses `SupplierPerformanceQuery` when bounded reporting is available;
- warehouse-valuation now uses `WarehouseValuationQuery` when bounded reporting is available;
- both endpoints accept a non-negative `offset` and propagate it through the bounded query contract;
- supplier-performance carries its requested reporting window into the repository query;
- warehouse-valuation uses a same-instant snapshot period because the underlying report is not time-ranged;
- legacy `repository.Reports` implementations remain supported for offset `0`;
- legacy implementations return HTTP `501 Not Implemented` for nonzero offsets instead of silently returning an incorrect page;
- JSON and CSV report response bodies remain unchanged;
- pagination metadata remains aligned with the actual query bounds;
- `/api/v1/meta` now reports `0.3.7` and has regression coverage to prevent version drift;
- no database migration was added;
- reporting remains read-only.

### Compatibility

The existing `repository.Reports` interface remains unchanged. `repository.BoundedReports` is still additive, so repositories can adopt bounded execution incrementally.

Clients that already use the supplier-performance or warehouse-valuation endpoints without `offset` continue to receive the existing behavior. Clients requesting a nonzero `offset` require a repository implementation that supports the additive bounded capability.

### Verification

The release changes include focused HTTP regression tests covering bounded capability selection, legacy fallback, offset validation, pagination metadata, query-period propagation, and API version reporting.

The GitHub integration used for this project can push repository changes and commits but does not create the GitHub Release object. Publish tag `v0.3.7` and these notes through the repository's Releases UI after the repository's own CI/test checks are confirmed.
