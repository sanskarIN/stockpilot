# StockPilot v0.5.5 — Release Metadata & API Compatibility CI Guardrails

**Version:** `0.5.5`  
**Previous version:** `0.5.4`  
**Release type:** Patch / release hardening  
**Branch:** `main`  
**Tag:** `v0.5.5`  
**Release date:** September 10, 2026  
**Database migration:** None

## Release focus

StockPilot v0.5.5 strengthens the release process around the existing API compatibility policy. The main goal is to prevent application release metadata from drifting between the repository `VERSION` file and the public `/api/v1/meta` endpoint.

## Highlights

- added `scripts/check-release-consistency.sh`;
- added `make release-check` for local release verification;
- added a dedicated `Release metadata consistency` GitHub Actions job;
- the CI guard validates that `VERSION` contains a semantic `MAJOR.MINOR.PATCH` value;
- the CI guard validates that `/api/v1/meta` exposes the same release version;
- aligned `VERSION` with `0.5.5`;
- aligned `/api/v1/meta` with `0.5.5`;
- aligned the API metadata regression test with `0.5.5`;
- kept the change independent of production credentials and production data;
- introduced no database migration.

## Reliability impact

This is intentionally a small hardening release. It does not change inventory mutation rules, purchase-order lifecycle behavior, reporting authorization semantics, or database schema.

The new consistency gate is deterministic and runs before the existing Go, Web, PostgreSQL, and Browser E2E validation jobs are considered part of a complete release validation cycle.

## API compatibility

The existing `/api/v1` contract remains unchanged. The release follows the repository's API compatibility policy:

- existing JSON field names are preserved;
- no request fields were made mandatory;
- no permission semantics were changed;
- no API version was changed;
- no response contract was removed or renamed.

The new check is a repository/release guardrail rather than a new API surface.

## Database

No database migration is introduced.

Users upgrading from v0.5.4 do not need to run a new migration for this release.

## Testing and verification

The intended release gate is:

- release metadata consistency check;
- Go module consistency;
- Go formatting;
- `go vet`;
- race-enabled Go tests;
- backend build;
- frontend typecheck/build;
- PostgreSQL migration smoke test;
- Chromium Playwright E2E;
- configured CodeQL/security checks;
- Android and extension checks where their workflows apply.

The release branch should not be considered fully verified until GitHub Actions reports the applicable required checks as successful on the final release commit.

## Upgrade

StockPilot v0.5.4 users can upgrade to v0.5.5 as a patch release.

No database migration is required.
