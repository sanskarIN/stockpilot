# StockPilot v0.3.9

## Report Count & Pagination Semantics

v0.3.9 adds an additive total-count capability for bounded supplier-performance and warehouse-valuation reports. Clients can now determine the complete result size without changing the existing JSON or CSV response bodies.

### Highlights

- added the optional `repository.CountedReports` capability;
- added PostgreSQL-backed supplier-performance and warehouse-valuation count queries;
- exposed complete result counts through the `X-Total-Count` response header;
- reused the same validated reporting period and pagination bounds for page and count operations;
- kept legacy repositories compatible when the optional counted capability is unavailable;
- exposed pagination response headers to approved browser origins through CORS;
- aligned `/api/v1/meta` with the `0.3.9` release version;
- added HTTP regression coverage for total-count headers and count-query bounds;
- added PostgreSQL integration coverage for count queries;
- kept offset pagination as the default and deferred cursor/streaming changes to a later milestone;
- added no database migration;
- kept reporting read-only.

### Compatibility

This release is additive. Existing repository implementations that only satisfy `repository.Reports` continue to work. Existing JSON and CSV response bodies, query parameters, and export formats remain unchanged.

`X-Total-Count` is emitted only when the configured repository provides the optional counted reporting capability. This avoids requiring all repository implementations to change at once.
