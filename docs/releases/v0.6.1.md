# StockPilot v0.6.1 — Complete Release Verification Gate

StockPilot v0.6.1 is a maintenance release focused on release correctness and making the local verification gate match the repository's actual multi-client surface area.

## Highlights

- advance the repository release version from `0.6.0` to `0.6.1`;
- align `/api/v1/meta` and its regression test with `0.6.1`;
- align the Web package, browser extension package/Manifest V3, and Android application with `0.6.1`;
- assign Android version code `6001` using the repository's deterministic semantic-version mapping;
- strengthen `make release-verify` so it covers backend, web, browser extension, and Android verification instead of stopping after the web build;
- preserve the version-aware release-readiness and release-consistency checks;
- keep the release migration-free and independent of production credentials/data.

## Release verification contract

The repository's complete local release gate is:

```text
make release-verify
```

It runs, in order:

```text
make release-check
make release-readiness
make vet
make test
make build
make web-build
make extension-check
make extension-test
make android-lint
make android-test
make android-build
```

The release-readiness and consistency scripts also validate the current `VERSION`, API metadata, regression test, changelog entry, and dedicated release documentation.

## Compatibility

- No intentional breaking `/api/v1` API change is introduced.
- No database migration is introduced.
- Existing production data is not modified by the release itself.
- Android version code advances from `6000` to `6001`.

## Verification policy

This release documentation describes the required gate; it is not itself evidence that every command has passed. The final release commit must pass the applicable GitHub Actions and security checks before publication.

Do not describe the release as bug-free based on static repository inspection alone. Functional, integration, platform, database, browser, Android, and security checks remain authoritative.

## Security

No production credentials or production data are required for the release verification process. Never commit secrets, signing keys, database passwords, or real deployment configuration.
