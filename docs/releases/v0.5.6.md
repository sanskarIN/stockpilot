# StockPilot v0.5.6 — Release Verification & Reproducibility Hardening

StockPilot v0.5.6 is a maintenance release focused on making release verification more deterministic and reducing the chance of shipping an inconsistent or unreproducible repository state.

## Highlights

- Add a release-readiness gate for the v0.5.6 repository state.
- Verify that `VERSION`, the changelog, and dedicated release documentation agree on the release being prepared.
- Reuse the existing read-only release metadata consistency check from v0.5.5.
- Verify Go module integrity with `go mod verify` when Go is available locally.
- Document the complete verification sequence required before publication.
- Keep release validation independent of production credentials and production data.

## Verification Model

The release should be validated in layers:

1. `bash ./scripts/check-release-consistency.sh`
2. `bash ./scripts/check-release-readiness.sh`
3. `go mod verify`
4. `go vet ./...`
5. `go test -race ./...`
6. `go build -trimpath ./cmd/server`
7. Web build and browser E2E checks
8. PostgreSQL migration/readiness smoke testing
9. Android lint/unit/build checks where the Android project is in scope
10. Extension checks/tests where the browser extension is in scope
11. GitHub Actions and CodeQL results on the final release commit

The release-readiness script is validation-only. It does not modify source files, application data, database state, tags, or GitHub releases.

## Compatibility

- No database migration is introduced by v0.5.6.
- No production-data dependency is introduced.
- No intentional breaking `/api/v1` change is introduced.
- Authentication and authorization contracts remain unchanged.
- Inventory, purchasing, reporting, Android, web, and extension workflows are not intentionally redefined by this release.

## Upgrade

Upgrade from v0.5.5 normally. No database migration or data transformation is required.

## Release Gate

Do not publish the `v0.5.6` tag until the final commit has successful applicable CI/security checks and the release-readiness checks complete successfully.
