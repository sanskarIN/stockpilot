# StockPilot v0.6.0 — Release Integrity & Verification Baseline

StockPilot v0.6.0 is the next pre-1.0 milestone after the v0.5.x release-integrity and reproducibility hardening track. This release aligns the active repository/API version metadata and strengthens the release record without introducing an intentional breaking API change.

## Highlights

- Advance the repository `VERSION` from `0.5.9` to `0.6.0`.
- Align `/api/v1/meta` with `0.6.0`.
- Align the API metadata regression test with `0.6.0`.
- Align the README current-development version with `0.6.0`.
- Align Web, browser extension, and Android client version metadata with `0.6.0`.
- Add this dedicated v0.6.0 release record.
- Preserve the version-aware release-readiness and release-consistency checks established in v0.5.8 and retained through v0.5.9.
- Keep the Android CI toolchain aligned with the minimum Gradle version required by the Android build plugin.

## Reliability and safety

- No database migration is introduced by this release.
- No production credentials are required for release metadata validation.
- No production data is required for release metadata validation.
- No intentional breaking `/api/v1` contract change is introduced.
- Release consistency remains validation-only.
- Release readiness derives its expected version from `VERSION` rather than a hard-coded patch number.

## Required verification gate

The v0.6.0 release must not be described as fully verified or considered publishable until the final release commit passes all applicable checks, including:

```text
make release-check
make release-readiness
make vet
make test
make build
make web-build
bash ./scripts/check-release-consistency.sh
```

Also require successful applicable Browser E2E, PostgreSQL migration/readiness smoke testing, CodeQL/security checks, Android checks, and extension checks where configured for the repository.

For local Go module verification, the release-readiness checker also runs:

```text
go mod verify
```

## Release integrity rule

Do not create or move the `v0.6.0` tag until the final release commit has a green applicable CI/security gate. Do not describe the release as fully verified based only on metadata inspection or an earlier commit.

## Upgrade

Upgrade normally from v0.5.9. No database migration or data transformation is required for this release.
