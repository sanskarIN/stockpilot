# StockPilot v0.3.4

## Reporting Export & Completeness

v0.3.4 standardizes report export metadata and makes bounded-report completeness conservative at the HTTP boundary.

### Highlights

- centralized CSV export content, download, and cache headers;
- supplier-performance and warehouse-valuation exports expose the same report metadata headers used by JSON reporting;
- generated-at, period, limit, offset, and completeness metadata are available to export consumers;
- completeness is `true` only when the returned result contains fewer items than the requested limit;
- preserved existing JSON and CSV response bodies and download filenames;
- retained CSV formula-injection sanitization;
- reporting remains read-only and requires no database migration.

### Compatibility

This release is additive for existing report consumers. Existing JSON fields and CSV columns are unchanged. Clients that do not use report metadata headers can continue consuming the response bodies as before.

### Completeness semantics

A bounded report is considered complete only when fewer rows than the requested limit are returned. If exactly the requested limit is returned, `X-Report-Complete` is `false` because the current repository interfaces do not expose a total-count contract that can prove there are no additional rows.
