# PostgreSQL Restore Drill

A backup is only useful when it can be restored. Run this drill against a disposable PostgreSQL instance before every stable release and after meaningful schema changes.

## Procedure

1. Create a fresh disposable PostgreSQL database with the same major version used in production.
2. Stop writes to the source environment or use a consistent backup generated by the operational backup script.
3. Create a backup with `make backup` and record the resulting file name and timestamp.
4. Restore the backup into the disposable database using the documented PostgreSQL restore command appropriate to the dump format.
5. Apply no source-control migrations yet. Confirm that the restored schema and data are readable.
6. Start StockPilot against the restored database with the production-like configuration but isolated network access.
7. Verify `/healthz` and `/readyz`.
8. Read representative catalog, inventory, purchasing, and reporting data.
9. Run the current migration set against the restored database when validating forward compatibility.
10. Record the recovery duration, backup size, schema version, and any corrective actions.

## Acceptance criteria

- Backup creation completes without a partial or truncated final file.
- Restore completes without integrity errors.
- Application readiness succeeds after restore.
- Representative business reads produce expected results.
- No production credentials or customer data are included in test artifacts.

## Retention

Use a protected destination for production backups and enforce retention outside source control. The application should not require credentials to be stored in the repository to execute scheduled backups.
